## Reporting a vulnerability

Please report security issues, such as authentication bypasses, token exposure, authorization failures, or unintended file access, through a private channel.

1. Check whether the repository's [Security Advisories](https://github.com/SSAFY-URAYAHA/DevLink_server/security/advisories) page provides a **Report a vulnerability** button. If available, use it to submit a private report.
2. If private reporting is unavailable, use [Issues](https://github.com/SSAFY-URAYAHA/DevLink_server/issues) only to ask maintainers for a private contact method, without describing the vulnerability.

Do not include exploitable reproduction steps, attack code, personal information, real passwords, or tokens in public Issues or PRs. A dedicated reporting email address and response deadline have not yet been established.

## What to include in a private report

- Affected version or commit, operating system, and relevant tool versions
- Impact and conditions under which the issue occurs
- Reproduction steps or a minimal example
- Logs or screenshots with secrets and personal information removed
- A possible remediation approach, if available

Investigate only in environments you own or are explicitly authorized to test. Do not access other users' data or disrupt services.

## Supported versions

Security support periods have not yet been defined for individual versions. Include the release tag or commit you used when reporting an issue. The scope of security fixes and disclosure timing will be decided after the issue has been assessed.

For general bugs and feature requests, use [Issues](https://github.com/SSAFY-URAYAHA/DevLink_server/issues). See the [contributing guide](CONTRIBUTING.md) for development participation.
